# 招待コードによる初期費用の出し分け — dev E2Eテスト結果 (2026-07-16)

対象: `https://dev.smamo.jp` の申込フロー。招待コードがある場合だけ、月額・年払いプランの初期費用（¥33,000）を無料にする変更を検証した。

実施時間: 約3時間。内部ブラウザでの画面確認と、StripeテストモードのAPI検証を組み合わせて実施した。

## 結果サマリ

| ケース | 結果 | 確認内容 |
|---|---|---|
| 招待コードなし × 月額 | PASS | 初期費用 ¥33,000 の表示、Stripe invoice item 作成、無料化metadataなし |
| 招待コードあり × 月額 | PASS（画面は紹介リンク適用状態） | 招待コード適用 ¥0 の表示、無料化metadata、初期費用 invoice item なし |
| 紹介リンク（`?ref=E2E-DEMO-A`） | PASS | コード自動入力・編集不可、代理店バナー、無料通知 |
| 招待コードなし × 年払い | PASS | 初期費用 ¥33,000 の表示、Stripe invoice item 作成 |
| 招待コードあり × 年払い | PASS（画面は紹介リンク適用状態） | 招待コード適用 ¥0 の表示、初期費用 invoice item なし |
| 2年契約 × 招待コードなし／あり | PASS | どちらも初期費用行および無料バッジ行なし |
| 無効な招待コード | API PASS / UI最終送信は未確認 | APIが `400` と `招待コードが無効です。` を返却 |

## 画面確認

### 月額・年払い

- 招待コードなしでは、Step 1 に初期費用無料の通知が表示されず、Step 2 に `初期費用（3日後の請求に同梱） ¥33,000` が表示された。
- 招待コードありでは、`招待コード適用で初期費用（¥33,000）が無料になります` の通知が表示された。Step 2 では通常の初期費用行は非表示となり、緑色の `初期費用 招待コード適用 ¥0` が表示された。
- 上記の挙動を月額・年払いの両方で確認した。

### 紹介リンク

- `?ref=E2E-DEMO-A` で開始すると、招待コード欄に `E2E-DEMO-A` が自動設定され、編集不可となった。
- `紹介コード E2E-デモ子A 適用中` のバナーと、初期費用無料の通知が表示された。

### 2年契約

- 招待コードの有無にかかわらず、Step 2 に初期費用の通常行・無料バッジ行のいずれも表示されなかった。

## Stripeテストモード検証

- 招待コードなしの月額・年払いでは、subscription metadata に `initial_fee_waived` と `agency_code` がなく、customer の invoice items に初期費用が1件作成された。
- 招待コード `E2E-DEMO-A` を明示的に送った月額・年払いでは、subscription metadata に `initial_fee_waived: invitation_code` と `agency_code: E2E-DEMO-A` が設定され、customer の invoice items に初期費用は作成されなかった。
- 作成したStripeテスト用サブスクリプション4件は、検証後にすべてキャンセル済み。

画面での無料表示は紹介リンクによる適用状態で確認した。招待コードを手入力した場合は、checkout API に `invitation_code: E2E-DEMO-A` を明示送信して同じ課金ロジックを確認している。手入力直後の通知表示を単独では確認していない。

## 無効コード

- 無効なコードに対する checkout API の応答は、HTTP `400`、エラーメッセージ `招待コードが無効です。` だった。
- Stripeカード入力後の最終送信画面で同メッセージが表示されることは、今回の実施範囲では未確認。API側の拒否動作は確認済み。

## 総合判定

初期費用の出し分けロジックは、月額・年払い・2年契約・紹介リンクの各パターンで期待どおりに動作した。無効コードのAPI拒否も確認済みであり、残作業は最終送信時の画面エラー表示の確認のみ。
